# ADR 0002：区分回放语义并由服务端执行工具安全策略

- 状态：已接受
- 日期：2026-07-28

## 背景

“回放”可能仅指查看历史，也可能意味着重新调用模型和外部工具。混用这些语义会制造错误的可复现性承诺，并可能重复执行有副作用的工具。

## 决策

AgentScope 定义三种互斥模式：

1. `visual`：只改变界面播放进度，不执行任何外部调用；
2. `fixture`：使用记录或固定响应验证编排；
3. `fork`：从完整 Checkpoint 创建新 Run 并重新执行。

任何重新执行都创建带 `parentRunId` 和 `forkedFromSpanId` 的 Child Run，不修改原 Run。

工具必须声明 `read_only`、`idempotent`、`side_effect`、`destructive` 或 `unknown`。服务端默认允许只读工具，幂等工具需要确认，其余工具使用历史结果或阻止；v1.0 不提供真实执行 destructive 工具的入口。

## 结果

- 用户可以区分“查看过去”和“重新影响外部世界”。
- Parent/Child 提供可审计的实验分支。
- 数据采集不完整时，节点必须显示阻止原因，不能伪装成可重放。
- UI 提示不是安全边界，最终策略由执行层强制。
